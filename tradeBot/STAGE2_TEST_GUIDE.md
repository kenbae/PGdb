# 2단계 테스트 가이드

## 📋 테스트 전 준비사항

### 1. 서버 실행 확인
```bash
# Process Manager 실행
cd C:\Users\배경호\Documents\코젠트\VSrepository\PGdb
python process_manager.py

# 브라우저에서 접속
http://localhost:8000
```

### 2. 필요한 서버 확인
- ✅ **Web Server** (포트 8888): `/signals`, `/positions`, `/matching` 페이지
- ✅ **Analyzer Server**: 신호 생성 및 이벤트 로깅
- ✅ **Order Server**: 주문 처리 (선택사항)

## 🧪 테스트 시나리오

### 시나리오 1: 타이밍 모델 학습 및 예측

#### 1-1. 데이터 준비
1. **Matching 페이지 접속**
   - URL: `http://localhost:8888/matching`
   - 로그인 필요 (인증 토큰 확인)

2. **필터 설정**
   - Symbol: 특정 심볼 선택 (예: BTCUSDT) 또는 All
   - Start Date: 데이터가 있는 날짜 선택
   - End Date: 데이터가 있는 날짜 선택
   - Time Window: 60분 (기본값)

3. **데이터셋 로드**
   - "데이터셋 새로고침" 버튼 클릭
   - 매칭된 데이터가 있는지 확인

#### 1-2. 타이밍 모델 학습
1. **"타이밍 모델 학습" 버튼 클릭**
   - 현재 필터 조건으로 모델 학습
   - 학습 결과 카드 확인:
     - 학습 샘플 수
     - 진입 샘플 수
     - 청산 샘플 수
     - 시장 상태 패턴 수
     - 진입/청산 타이밍 통계

2. **학습 결과 확인**
   - 진입 타이밍 통계: 평균, 중앙값, 25%/75% 분위수
   - 청산 타이밍 통계: 평균, 중앙값, 25%/75% 분위수

#### 1-3. 타이밍 예측 테스트
1. **Signals 페이지 접속**
   - URL: `http://localhost:8888/signals`

2. **신호 선택**
   - 신호 테이블에서 신호 선택
   - 또는 신호 상세 모달 열기

3. **타이밍 예측 실행**
   - 신호 상세 모달에서 "⏱️ 타이밍 예측" 버튼 클릭
   - 또는 테이블에서 타이밍 추천 버튼 클릭

4. **예측 결과 확인**
   - 진입 타이밍: 신호 생성 후 몇 분 후 진입 추천
   - 청산 타이밍: 진입 후 몇 분 후 청산 추천
   - 진입 추천: 진입 여부 판단 (추천/비추천)
   - 신뢰도: 예측 신뢰도 (%)
   - 시장 상태: 트렌드, 변동성, RSI 상태

---

### 시나리오 2: 정책 모델 학습 및 추천

#### 2-1. 정책 모델 학습
1. **Matching 페이지 접속**
   - URL: `http://localhost:8888/matching`

2. **필터 설정 및 데이터 로드**
   - 충분한 매칭 데이터가 있는 기간 선택
   - "데이터셋 새로고침" 클릭

3. **"정책 모델 학습" 버튼 클릭**
   - 학습 진행 중 표시
   - 학습 결과 확인:
     - 학습 샘플 수
     - 정책 샘플 수
     - 시장 상태 패턴 수
     - 전략 패턴 수
     - 파라미터 추천 수

#### 2-2. 정책 요약 확인
1. **"정책 요약" 버튼 클릭**
   - 최고 성과 시장 상태 목록 확인
   - 최고 성과 전략 목록 확인
   - 각 항목별 승률, 평균 수익률, 추천 등급 확인

#### 2-3. 정책 추천 테스트
1. **Signals 페이지 접속**
   - URL: `http://localhost:8888/signals`

2. **신호 선택 및 정책 추천**
   - 신호 상세 모달에서 "🎯 정책 추천" 버튼 클릭
   - 또는 테이블에서 정책 추천 버튼 클릭

3. **추천 결과 확인**
   - 진입 추천: 진입 여부 판단 (추천/비추천)
   - 진입 타이밍: 최적 진입 시간
   - 청산 타이밍: 최적 청산 시간
   - 가격 조정: 신호 가격 대비 조정 권장사항
   - 리스크:리워드: 권장 리스크:리워드 비율
   - 파라미터 추천: RSI 범위 등
   - 추천 이유: 승률, 평균 수익률 기반 설명

---

### 시나리오 3: 전체 워크플로우 테스트

#### 3-1. 데이터 수집
1. **신호 생성 확인**
   - Analyzer Server가 실행 중인지 확인
   - 신호가 생성되는지 확인 (`/signals` 페이지)

2. **포지션 데이터 동기화**
   - Positions 페이지 접속
   - "Sync Binance" 버튼 클릭
   - 날짜 선택 후 동기화
   - 연결 상태 및 진행 과정 확인

#### 3-2. 매칭 확인
1. **Matching 페이지 접속**
   - 필터 설정 (Symbol, 날짜, Match Status)
   - 데이터셋 로드
   - 매칭 결과 확인:
     - Total Signals
     - Matched Count
     - Match Rate
     - Avg PnL
     - Win Rate

#### 3-3. 학습 및 추천
1. **타이밍 모델 학습**
   - "타이밍 모델 학습" 클릭
   - 학습 결과 확인

2. **정책 모델 학습**
   - "정책 모델 학습" 클릭
   - 학습 결과 확인

3. **정책 요약 확인**
   - "정책 요약" 클릭
   - 최고 성과 패턴 확인

4. **실제 신호에 적용**
   - Signals 페이지에서 최신 신호 선택
   - 타이밍 예측 및 정책 추천 확인
   - 추천 내용이 합리적인지 검토

## 🐛 문제 해결

### 학습 샘플 부족
**증상**: "학습 샘플 부족" 메시지 표시

**해결 방법**:
1. 더 긴 기간의 데이터 선택
2. 매칭된 데이터가 충분한지 확인 (최소 10개 이상 권장)
3. 사용자 액션이 기록되어 있는지 확인

### 예측 결과가 "데이터 부족"
**증상**: 모든 예측이 기본값으로 표시됨

**해결 방법**:
1. 먼저 모델 학습 실행
2. 학습이 성공했는지 확인
3. 해당 시장 상태에 대한 학습 데이터가 있는지 확인

### API 오류 (500, 401 등)
**증상**: API 호출 실패

**해결 방법**:
1. 서버 로그 확인 (콘솔 출력)
2. 인증 토큰 확인 (로그인 필요)
3. 데이터베이스 연결 확인
4. 필수 서버가 실행 중인지 확인

## 📊 예상 결과

### 정상적인 경우
- **타이밍 모델 학습**: 진입 평균 10~30분, 청산 평균 2~6시간
- **정책 모델 학습**: 시장 상태별 패턴 5~20개, 전략별 패턴 3~10개
- **타이밍 예측**: 신뢰도 30~80%, 합리적인 시간 범위
- **정책 추천**: 승률 기반 진입 추천, 구체적인 타이밍 및 파라미터 제안

### 데이터가 부족한 경우
- 학습 샘플 부족 메시지
- 기본값으로 예측 (신뢰도 0%)
- "데이터 부족" 추천 등급

## 💡 팁

1. **충분한 데이터 확보**: 최소 50개 이상의 매칭된 샘플 권장
2. **다양한 시장 상태**: 다양한 트렌드/변동성 조합이 있으면 더 정확한 학습
3. **정기적 재학습**: 새로운 데이터가 쌓이면 주기적으로 재학습
4. **결과 검증**: 추천 결과를 실제 거래와 비교하여 모델 개선
